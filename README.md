# Underwood Text Visualizer

구글폼 응답을 **실시간으로 읽어 화면에 띄우는** 웹앱입니다.
서버가 필요 없어 GitHub Pages 같은 정적 호스팅에 그대로 올릴 수 있습니다.

| 페이지 | 설명 |
|--------|------|
| `index.html` | **불안, 그리고 위로** — 화면을 위/아래로 나눠 서로 다른 시트 열의 응답을 떠다니게 표시 |
| `bubbles.html` | 초기 버전 — 단일 열의 응답을 떠다니는 버블로 표시 |

---

## 동작 원리

```
구글폼 응답 ──> 연결된 구글시트 ──(N초마다 Sheets API 조회)──> 웹페이지가 새 행 감지 ──> 화면에 등장
```

구글폼에는 실시간 푸시 API가 없어, 연결된 시트를 짧은 간격으로 조회하는 방식입니다.
응답 후 화면에 뜨기까지 최대 "폴링 간격(기본 5초)" 정도의 지연이 있습니다.

---

## 준비 (한 번만 설정)

### 1) 폼 응답을 시트에 연결
구글폼 → **응답** 탭 → 시트 아이콘 → **스프레드시트 만들기/연결**

### 2) 시트를 공개(뷰어)로 설정
연결된 시트 → **공유** → **링크가 있는 모든 사용자** → 권한 **뷰어**

> 표시할 열만 노출됩니다. 민감정보가 있으면 표시할 열만 담은 별도 시트로 분리하세요.

### 3) Google Cloud API 키 발급
1. https://console.cloud.google.com → 프로젝트 생성
2. **API 및 서비스 → 라이브러리 → "Google Sheets API"** → **사용 설정**
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**
4. 키 편집 → **애플리케이션 제한 = 웹사이트(HTTP 리퍼러)** → 아래 주소 등록
   ```
   https://<사용자명>.github.io/*
   http://localhost:8000/*      ← 로컬 테스트용
   ```
5. **API 제한 = Google Sheets API** 로 한정

### 4) 웹앱에 입력
페이지 우측 상단 ⚙️ → 값 입력 후 **열 불러오기 → 열 선택 → 저장하고 시작**

| 항목 | 설명 |
|------|------|
| Google API 키 | 3)에서 만든 키 |
| 스프레드시트 ID | 시트 URL 의 `/d/` 와 `/edit` 사이 문자열 |
| 탭(시트) 이름 | 보통 `설문지 응답 시트1` |
| 폴링 간격(초) | 기본 5 |
| 화면당 단어 개수 | 4~300 (위/아래 각각) |
| 글자 크기 | 0.6× ~ 2.0× 배율 |
| 떠다니는 속도 | 0.2× ~ 3.0× (1× 가 기본 속도) |
| 위쪽 열 / 아래쪽 열 | 각 절반에 표시할 질문(열)과 라벨 |

설정은 브라우저(localStorage)에 저장되어 다음 방문 시 자동 연결됩니다.

## GitHub Pages 배포

1. **Settings → Pages**
2. Source: `Deploy from a branch`
3. Branch: `main`, 폴더 `/ (root)` → **Save**
4. 잠시 후 접속:
   - `https://<사용자명>.github.io/UnderwoodTextVisualizer/` → 불안/위로 화면
   - `https://<사용자명>.github.io/UnderwoodTextVisualizer/bubbles.html` → 버블 화면

---

## 로컬에서 확인하기

`file://` 로 직접 열면 API 키의 리퍼러 제한에 걸려
`Requests from referer null are blocked` (403) 오류가 납니다.
로컬 서버로 여세요:

```bash
python3 -m http.server 8000
# http://localhost:8000/ 접속
```

그리고 API 키 리퍼러 목록에 `http://localhost:8000/*` 를 추가하면 됩니다.

## 사용 팁
- 위/아래 화면을 **더블클릭**하면 테스트 단어가 뜹니다(15초 후 자동으로 사라짐).
- **같은 답변이 또 들어오면 단어를 추가하지 않고 기존 단어가 커집니다.**
  많이 나온 답변일수록 크고 굵고 진하게 표시됩니다(앞뒤 공백·대소문자 차이는 같은 답으로 취급).
- 매 폴링마다 시트 전체와 화면을 맞추므로, **시트에서 행을 지우면 화면에서도 사라집니다.**
  부적절한 응답은 시트에서 그 행을 삭제하면 폴링 간격 안에 정리되고,
  중복 중 일부만 지우면 그만큼 **단어가 다시 작아집니다.**
- 정원(단어 개수)을 넘으면 **가장 오래된 단어부터 밀려납니다.** 단, 같은 답변이 다시 들어오면
  최신으로 갱신되므로 자주 나오는 단어는 계속 남습니다.
- 화면에 남아 있는 단어는 다시 그리지 않아 깜빡임 없이 계속 떠다닙니다.
- 설정창의 슬라이더를 움직이면 **뒤 화면에 실시간 미리보기**로 반영됩니다.
- 발표/행사 화면은 전체화면(F11)으로 띄우면 좋습니다.

## 주의
- API 키는 정적 페이지에 노출됩니다 → **리퍼러 제한 + Sheets API 한정**을 반드시 유지하세요.
- 제한을 해제해야 할 일이 생기면, 이후 **키를 새로 발급**하고 기존 키는 삭제하는 것이 안전합니다.
