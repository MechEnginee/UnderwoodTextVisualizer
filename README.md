# 🫧 실시간 응답 버블 (Google Form Live Bubbles)

구글폼에 응답이 들어오면, 연결된 구글시트를 **주기적으로 읽어(폴링)** 새 답변을
화면에 **떠다니는 버블**로 실시간 표시하는 단일 페이지 웹앱입니다.
별도 서버가 필요 없어 **GitHub Pages** 같은 정적 호스팅에 그대로 올릴 수 있습니다.

- 방식: Google Sheets API v4 폴링 (기본 5초 간격)
- 표시: 지정한 **특정 질문(열)** 의 답변만 버블로 표시
- 개인정보: 이름/이메일 등은 표시하지 않음(선택한 열만 노출)

---

## 동작 원리

```
구글폼 응답 ──> 연결된 구글시트 ──(N초마다 Sheets API로 조회)──> 웹페이지가 새 행 감지 ──> 버블 등장
```

> 참고: 구글폼에는 실시간 푸시 API가 없어, 시트를 짧은 간격으로 조회하는 방식입니다.
> 응답 후 화면에 뜨기까지 최대 "폴링 간격(기본 5초)" 정도의 지연이 있습니다.

---

## 준비 (한 번만 설정)

### 1) 폼 응답을 시트에 연결
구글폼 → **응답** 탭 → 우측 상단 시트 아이콘 → **스프레드시트 만들기/연결**

### 2) 시트를 공개(뷰어)로 설정
정적 페이지에서 API 키만으로 읽으려면 시트가 공개 상태여야 합니다.
연결된 시트 → **공유** → **링크가 있는 모든 사용자** → 권한 **뷰어**
> 표시하는 열만 노출되며, 시트 전체 링크를 공유하지 않는 한 검색에는 노출되지 않습니다.
> 민감정보가 있으면 표시할 열만 담은 별도 시트로 분리하세요.

### 3) Google Cloud API 키 발급
1. https://console.cloud.google.com → 프로젝트 생성
2. **API 및 서비스 → 라이브러리 → "Google Sheets API"** 검색 후 **사용 설정**
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**
4. 생성된 키 복사
5. (권장) 키 편집 → **애플리케이션 제한 = HTTP 리퍼러** → 본인 GitHub Pages 주소 추가
   (예: `https://<사용자명>.github.io/*`), **API 제한 = Google Sheets API** 로 한정

### 4) 웹앱에 입력
페이지 우측 상단 ⚙️ → 아래 값 입력 후 **열 불러오기 → 질문 선택 → 저장하고 시작**

| 항목 | 설명 |
|------|------|
| Google API 키 | 3)에서 만든 키 |
| 스프레드시트 ID | 시트 URL 의 `/d/` 와 `/edit` 사이 문자열 |
| 탭(시트) 이름 | 보통 `설문지 응답 시트1` |
| 폴링 간격(초) | 기본 5 (너무 짧으면 API 할당량 소모↑) |
| 띄울 질문(열) | "열 불러오기" 후 목록에서 선택 |

설정은 브라우저(localStorage)에 저장되어 다음 방문 시 자동 연결됩니다.

---

## GitHub Pages 배포

1. 이 저장소에 `index.html` 이 있는지 확인
2. GitHub → **Settings → Pages** → Source: `Deploy from a branch`
3. Branch: 배포할 브랜치(예: `main`), 폴더 `/ (root)` → **Save**
4. 잠시 후 `https://<사용자명>.github.io/UnderwoodTextVisualizer/` 접속

---

## 사용 팁
- 레이아웃 확인: 화면을 **더블클릭**하면 테스트 버블이 뜹니다.
- 처음 로딩 시 **기존 답변을 모두** 버블로 띄우고, 이후 들어오는 **새 답변**도 계속 추가됩니다.
- 버블은 사라지지 않고 **화면 안에서 계속 떠다니며 벽에 튕깁니다.** 답변이 아주 많으면(수백 개) 화면이 꽉 찰 수 있습니다.
- 발표/행사 화면은 전체화면(F11)으로 띄우면 좋습니다.

## 제약 / 주의
- API 키는 정적 페이지에 노출됩니다 → 반드시 **리퍼러 제한 + Sheets API 한정**으로 오남용을 막으세요.
- Sheets API 무료 할당량 한도 내에서 폴링 간격을 정하세요(5초면 하루 종일도 충분).
- 진짜 "1초 이내" 즉시성이 필요하면 Apps Script `onFormSubmit` + 웹훅/실시간 DB 방식으로 확장할 수 있습니다.
